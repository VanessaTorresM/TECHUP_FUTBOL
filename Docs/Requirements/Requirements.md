### RF01: Registro de Torneo
| Campo                     | Detalle                                                                                                                                                                                                                              |

| **Código**                | RF01                                                                                                                                                                                                                                 |
| **Nombre**                | Registro de Torneo                                                                                                                                                                                                                   |
| **Descripción**           | El organizador podrá crear un torneo con información básica, iniciarlo, finalizarlo y consultarlo.                                                                                                                                   |
| **Cómo se ejecutará**     | A través de un formulario administrativo donde se definen los parámetros globales del evento.                                                                                                                                        |
| **Actor principal**       | Organizador                                                                                                                                                                                                                          |
| **Precondiciones**        | El usuario debe estar autenticado con rol de Organizador.                                                                                                                                                                            |
| **Datos de Entrada**      | **1.** Fecha inicial (Fecha, Obligatorio). <br> **2.** Fecha final (Fecha, Obligatorio). <br> **3.** Cantidad de equipos (Numérico, Obligatorio). <br> **4.** Costo por equipo (Moneda, Obligatorio).                                |
| **Datos de Salida**       | **1.** Confirmación de registro exitoso. **2.** Estado activo                                                                                                                                                                        |

| **Flujo Alterno**         | 1) Si faltan datos obligatorios, <br/>2) El sistema muestra un mensaje de error y no permite el guardado.                                                                                                                            |

### RF02: Registro de Jugadores
| Campo                     | Detalle                                                                                                                                                                                                                                                      |
|:--------------------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Código**                | RF02                                                                                                                                                                                                                                                         |
| **Nombre**                | Registro de Jugadores                                                                                                                                                                                                                                        |
| **Descripción**           | Los participantes podrán registrarse, crear su perfil deportivo (posiciones, dorsal, foto), marcar su disponibilidad para el torneo(permitiendo que los capitanes lo contacten) y prodrá aceptar o rechazar invitaciones de capitanes.                       |
| **Cómo se ejecutará**     | Mediante un módulo de registro y edición de perfil de usuario dentro de la plataforma.                                                                                                                                                                       |
| **Actor principal**       | Estudiante, Graduado, Profesor, Personal Administrativo, Familiar.                                                                                                                                                                                           |
| **Precondiciones**        | Contar con correo institucional (personal ECI) o Gmail (exclusivo para familiares).                                                                                                                                                                          |
| **Datos de Entrada**      | **1.** Correo electrónico (Email, Obligatorio). <br> **2.** Posiciones de juego (Selección, Obligatorio). <br> **3.** Número dorsal (Numérico, Obligatorio). <br> **4.** Foto de perfil (Imagen, Opcional). <br> **5.** Estado de disponibilidad (Booleano). |

### RF03: Creación y gestión de equipos
| Campo                     | Detalle                                                                                                                                                                                                                                                                                                 |
|:--------------------------|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Código**                | RF03                                                                                                                                                                                                                                                                                                    |
| **Nombre**                | Creación y gestión de equipos                                                                                                                                                                                                                                                                           |
| **Descripción**           | Permite a un usuario con perfil de jugador crear un equipo, asignar una identidad visual (nombre, escudo, colores) e invitar a otros jugadores registrados.                                                                                                                                             |
| **Cómo se ejecutará**     | A través de un formulario de creación de equipo y un panel de gestión de nómina para el capitán.                                                                                                                                                                                                        |
| **Actor principal**       | Capitán                                                                                                                                                                                                                                                                                                 |
| **Precondiciones**        | 1) El usuario debe estar registrado. <br/>2) El usuario no debe pertenecer a ningún equipo actualmente.                                                                                                                                                                                                 |
| **Datos de Entrada**      | **1.** Nombre del equipo (Texto, Obligatorio). <br> **2.** Escudo del equipo (Imagen, Opcional). <br> **3.** Colores del uniforme (Texto, Obligatorio). <br> **4.** Invitaciones a jugadores (ID/Búsqueda, Obligatorio).                                                                                |
| **Datos de Salida**       | **1.** Confirmación de creación de equipo exitosa. <br/>**2.** Notificación de invitaciones enviadas a los jugadores invitados.                                                                                                                                                                         |
| **Flujo Básico**          | 1) El Capitán ingresa el nombre, colores y carga el escudo de su equipo. <br/>2) El Sistema valida que el nombre del equipo no esté duplicado. <br/>3) El Capitán busca jugadores disponibles y envía las invitaciones. <br/>4) El Sistema vincula a los jugadores que acepten la invitación al equipo. |
| **Flujo Alterno**         | 1) Si el equipo no cumple con la cuota mínima de jugadores (7), <br/>2) El sistema no permitirá realizar el proceso de inscripción formal al torneo.                                                                                                                                                    |
| **Reglas de Negocio**     | 1) Un equipo debe tener un mínimo de 7 y un máximo de 12 jugadores. <br/>2) Más de la mitad de los miembros deben pertenecer a Ingeniería de Sistemas, IA, Ciberseguridad o Estadística. <br> 3) Un jugador no puede pertenecer a dos equipos simultáneamente.                                          |
| **Anexos**                | **Prototipos:** <br/>Mockup de Gestión de Equipos y Nómina.  <br> **Abreviaturas:** N/A.                                                                                                                                                                                                                |

### RF04: Búsqueda de Jugadores
| Campo                     | Detalle                                                                                                                                                                                                                                                                        |
|:--------------------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Código**                | RF04                                                                                                                                                                                                                                                                           |
| **Nombre**                | Búsqueda de Jugadores                                                                                                                                                                                                                                                          |
| **Descripción**           | El sistema debe permitir a los capitanes localizar jugadores disponibles mediante diversos filtros de búsqueda para integrarlos a sus equipos.                                                                                                                                 |
| **Cómo se ejecutará**     | A través de un buscador con filtros dinámicos en el panel de gestión del capitán.                                                                                                                                                                                              |
| **Actor principal**       | Capitán                                                                                                                                                                                                                                                                        |
| **Precondiciones**        | 1) El capitán debe estar autenticado. <br/>2) Debe existir una base de datos de jugadores con perfiles deportivos activos.                                                                                                                                                     |
| **Datos de Entrada**      | **1.** Posición (Portero, defensa, volante, delantero). <br> **2.** Semestre (Numérico). <br> **3.** Edad (Numérico). <br> **4.** Género (Selección). <br> **5.** Nombre (Texto). <br> **6.** Identificación (Numérico).                                                       |
| **Datos de Salida**       | **1.** Listado de jugadores que coinciden con los filtros aplicados. <br/>**2.** Perfil resumido de cada jugador encontrado.                                                                                                                                                   |
| **Flujo Básico**          | 1) El Capitán accede al módulo de búsqueda. <br/>2) El Capitán selecciona o ingresa los criterios de búsqueda (filtros). <br/>3) El Sistema consulta la base de datos y filtra a los jugadores disponibles. <br/>4) El Sistema muestra los resultados en una lista organizada. |
| **Flujo Alterno**         | 1) Si no existen jugadores que coincidan con los criterios ingresados, <br/>2) El sistema muestra un mensaje indicando "No se encontraron resultados para esta búsqueda".                                                                                                      |
| **Reglas de Negocio**     | 1) El filtro de semestre solo aplica para aquellos usuarios registrados con el perfil de estudiante. <br/>2) Solo se deben mostrar jugadores que tengan marcado su estado como "Disponible".                                                                                   |
| **Anexos**                | **Prototipos:** <br/>Mockup de Buscador de Jugadores y Filtros. <br> **Reglas de Negocio:** 1. La búsqueda por identificación debe ser exacta para garantizar la privacidad. <br> **Abreviaturas:** N/A                                                                        |

### RF05: Inscripción y pagos
| Campo                     | Detalle                                                                                                                                                                                                                                                                                                                                                       |
|:--------------------------|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Código**                | RF05                                                                                                                                                                                                                                                                                                                                                          |
| **Nombre**                | Inscripción y pagos                                                                                                                                                                                                                                                                                                                                           |
| **Descripción**           | El sistema debe permitir al capitán de cada equipo cargar el comprobante de pago realizado externamente para que el organizador valide su participación oficial en el torneo.                                                                                                                                                                                 |
| **Cómo se ejecutará**     | A través de un módulo de carga de archivos para el capitán y una bandeja de validación para el organizador.                                                                                                                                                                                                                                                   |

| **Datos de Salida**       | **1.** Notificación de recepción de documento. <br/>**2.** Cambio de estado del equipo a "Aprobado (inscrito)" tras la validación.                                                                                                                                                                                                                            |

### RF06: Configurar Torneo

|:--------------------------|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|

| **Nombre**                | Configurar Torneo                                                                                                                                                                                                                                                                                                                            |
| **Descripción**           | El sistema debe permitir al organizador, una vez creado el torneo, definir los parámetros operativos, normativos y logísticos necesarios para su ejecución.                                                                                                                                                                                  |
| **Cómo se ejecutará**     | Mediante un panel de configuración avanzada disponible exclusivamente para el rol de Organizador.                                                                                                                                                                                                                                            |

| **Datos de Salida**       | **1.** Confirmación de configuración guardada exitosamente. <br/>**2.** Parámetros del torneo publicados para consulta de los usuarios.                                                                                                                                                                                                      |

### RF07: Alineaciones

| Campo                     | Detalle                                                                                                                                                                                                                                                                                                                                                                                    |
|:--------------------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Código**                | RF07                                                                                                                                                                                                                                                                                                                                                                                       |
| **Nombre**                | Alineaciones                                                                                                                                                                                                                                                                                                                                                                               |
| **Descripción**           | El sistema debe permitir al **capitán** organizar la alineación del equipo **antes de cada partido**, seleccionando titulares y reservas, eligiendo una formación y ubicando a los jugadores visualmente en la cancha. Además, capitanes y jugadores podrán consultar la alineación del rival.                                                                                             |
| **Cómo se ejecutará**     | Mediante un módulo por partido donde el capitán: elige formación, selecciona titulares y reservas, y dispone a los titulares en un esquema visual de cancha; el sistema publica la alineación para consulta de quien tenga permisos.                                                                                                                                                       |
| **Actor principal**       | Capitán                                                                                                                                                                                                                                                                                                                                                                                    |
| **Precondiciones**        | 1) El capitán debe estar autenticado con rol de capitán. <br> 2) El equipo debe existir y tener una cantidad de jugadores válida para que la alineación se construya. <br> 3) Debe existir un partido programado para el equipo.                                                                                                                                                           |
| **Datos de Entrada**      | **1.** Partido (ID del partido, Obligatorio). <br> **2.** Formación (Selección, Obligatorio). <br> **3.** Titulares (Lista de jugadores, Obligatorio). <br> **4.** Reservas (Lista de jugadores, Obligatorio). <br> **5.** Ubicación visual en cancha (Posiciones, Obligatorio para titulares).                                                                                            |
| **Datos de Salida**       | **1.** Confirmación de guardado de alineación. <br> **2.** Visualización de alineación (cancha + titulares + reservas). <br> **3.** Alineación disponible para consulta por capitanes y jugadores.                                                                                                                                                                                         |
| **Flujo Básico**          | 1) El Capitán ingresa al partido y abre el módulo de alineación. <br> 2) El Capitán elige una formación. <br> 3) El Capitán selecciona **titulares** y **reservas** de la nómina del equipo. <br> 4) El Capitán ubica visualmente a los titulares en la cancha. <br> 5) El Sistema guarda la alineación y la publica para consulta.                                                        |
| **Flujo Alterno**         | 1) Si no se cumple la cantidad requerida de jugadores para jugar el partido, el sistema no permite guardar/publicar la alineación y muestra mensaje de ajuste.                                                                                                                                                                                                                             |
| **Reglas de Negocio**     | 1) Durante cada partido **participarán minimo 7 estudiantes por equipo**. <br> 2) Antes de cada partido, el capitán define quiénes participarán; los demás quedan como **reservas**. <br> 3) Capitanes y jugadores pueden **consultar la alineación del equipo rival**. <br> 4) No se permiten cambios de equipo entre participantes; se juega el torneo con la nómina inicial del equipo. |
| **Anexos**                | **Prototipos:** Mockup de módulo de alineación. <br> **Reglas de Negocio:** 1) Participan minimo 7 por partido. 2) Definición de reservas. 3) Consulta de alineación rival. 4) Nómina fija durante el torneo. <br> **Abreviaturas:** N/A                                                                                                                                                   |

### RF08: Registro de Partidos

| Campo                     | Detalle                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
|:--------------------------|:------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Código**                | RF08                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Nombre**                | Registro de Partidos                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Descripción**           | El sistema debe permitir al **organizador** registrar la información oficial de un partido, incluyendo **marcador**, **goleadores**, **tarjetas amarillas** y **tarjetas rojas**, para mantener actualizada la información del torneo.                                                                                                                                                                                                                                                    |
| **Cómo se ejecutará**     | Mediante un módulo administrativo de “Partidos” donde el organizador selecciona un partido programado y diligencia el resultado e incidencias.                                                                                                                                                                                                                                                                                                                                            |
| **Actor principal**       | Organizador                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Precondiciones**        | 1) El usuario debe estar autenticado con rol de Organizador. <br> 2) Debe existir un torneo activo o en progreso. <br> 3) El partido debio existir y estar terminado.                                                                                                                                                                                                                                                                                                                     |
| **Datos de Entrada**      | **1.** Partido (ID del partido, Obligatorio). <br> **2.** Marcador final (Goles equipo A, goles equipo B, Obligatorio). <br> **3.** Goleadores (Lista de registros: jugador + equipo, Opional). <br> **4.** Tarjetas amarillas (Lista de registros: jugador + equipo, Opcional). <br> **5.** Tarjetas rojas (Lista de registros: jugador + equipo, Opcional).                                                                                                                             |
| **Datos de Salida**       | **1.** Confirmación de registro exitoso del partido. <br> **2.** Partido actualizado con resultado e incidencias. <br> **3.** Información del torneo actualizada para su consulta.                                                                                                                                                                                                                                                                                                        |
| **Flujo Básico**          | 1) El Organizador ingresa al módulo de gestión de partidos. <br> 2) El Organizador selecciona el partido a registrar. <br> 3) El Organizador ingresa el marcador final. <br> 4) El Organizador registra los goleadores y las tarjetas si es que existen. <br> 5) El Sistema valida consistencia. <br> 6) El Sistema guarda el registro del partido y deja el resultado disponible para consulta.                                                                                          |
| **Flujo Alterno**         | 1) Si el Organizador intenta registrar un goleador o tarjeta para un jugador que **no pertenece** a ninguno de los equipos del partido, el sistema bloquea el guardado y muestra error. <br> 2) Si el Organizador registra un marcador con goles y no agrega goleadores, el sistema muestra advertencia y no permite guardar hasta completar la información. <br> 3) Si el partido ya tiene resultado registrado, el sistema informa y permite actualizarlo únicamente por el organizador |
| **Reglas de Negocio**     | 1) Solo el **Organizador** puede registrar resultados e incidencias de un partido. <br> 2) Los goleadores y sancionados deben pertenecer a los equipos que disputaron el partido. <br> 3) El registro del partido debe reflejar el resultado oficial que se publicará como información del torneo.                                                                                                                                                                                        |
| **Anexos**                | **Prototipos:** Mockup de formulario de registro de partido. <br> **Reglas de Negocio:** Validación de pertenencia de jugadores al partido y control de permisos por rol. <br> **Abreviaturas:** N/A                                                                                                                                                                                                                                                                                      |
| **Historial de revisión** | **Elaborado por:** Santiago Cajamarca <br> **Aprobado por:** Juan Esteban Rodriguez <br> **Fecha:** 04/03/2026 <br> **Descripción y Justificación de cambios:**                                                                                                                                                                                                                                                                                                                           |


### RF09: Consulta de partidos

| Campo                     | Detalle                                                                                                                                                                                                                                                                                        |
|:--------------------------|:-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Código**                | RF09                                                                                                                                                                                                                                                                                           |
| **Nombre**                | Consulta de partidos                                                                                                                                                                                                                                                                           |
| **Descripción**           | El sistema debe permitir al **árbitro** consultar la información de los partidos que debe arbitrar, incluyendo **fecha y hora**, **cancha** y **equipos** que disputarán el encuentro.                                                                                                         |
| **Cómo se ejecutará**     | Mediante un módulo de “Mis partidos” para el árbitro, con un listado de partidos asignados y una vista de detalle por partido.                                                                                                                                                                 |

### RF10: Tabla de Posiciones

| Campo                     | Detalle                                                                                                                                                                                                                                                                                                                                                    |
|:--------------------------|:-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Código**                | RF10                                                                                                                                                                                                                                                                                                                                                       |
| **Nombre**                | Tabla de Posiciones                                                                                                                                                                                                                                                                                                                                        |
| **Descripción**           | El sistema debe **calcular y mostrar automáticamente** la tabla de posiciones por equipo a partir de los resultados registrados, incluyendo: **partidos jugados, ganados, empatados, perdidos, goles a favor, goles en contra, diferencia de gol y puntos**.                                                                                               |
| **Cómo se ejecutará**     | Mediante un módulo de consulta del torneo que presente la tabla de posiciones. La tabla se recalcula cada vez que se registra o actualiza el resultado de un partido.                                                                                                                                                                                      |
| **Actor principal**       | Usuario autenticado (Participante/Capitán/Organizador/Árbitro/Administrador)                                                                                                                                                                                                                                                                               |
| **Precondiciones**        | 1) Debe existir un torneo creado y visible para los usuarios. <br> 2) Debe existir al menos un equipo inscrito. <br> 3) Para que la tabla tenga valores distintos de cero, deben existir partidos con resultados registrados.                                                                                                                              |
| **Datos de Entrada**      | **1.** Torneo (ID del torneo, Obligatorio). <br> **2.** Fase o tipo de tabla (Opcional). <br> **3.** Criterios de visualización (Opcional).                                                                                                                                                                                                                |

### RF11: Llaves Eliminatorias

| Campo                     | Detalle                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
|:--------------------------|:------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Código**                | RF11                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Nombre**                | Llaves Eliminatorias                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Descripción**           | El sistema debe **generar automáticamente** el cuadro de eliminación directa del torneo, incluyendo la creación de los **partidos iniciales de manera aleatoria**, y la progresión por fases: **cuartos de final, semifinal y final**, actualizando los cruces conforme se registren los resultados.                                                                                                                                                                                                                                                                                                        |
| **Cómo se ejecutará**     | Mediante un módulo del torneo donde el organizador activa la generación del bracket y el sistema construye las llaves; luego, el sistema avanza automáticamente los equipos ganadores a la siguiente fase cuando se registran resultados.                                                                                                                                                                                                                                                                                                                                                                   |
| **Actor principal**       | Organizador                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Precondiciones**        | 1) El usuario debe estar autenticado con rol de Organizador. <br> 2) Debe existir un torneo en estado **Activo** o **En progreso**. <br> 3) Debe existir el conjunto de equipos clasificados para eliminación directa. <br> 4) Debe estar definida la cantidad de equipos que ingresan a llaves.                                                                                                                                                                                                                                                                                                            |
| **Datos de Entrada**      | **1.** Torneo (ID del torneo, Obligatorio). <br> **2.** Cantidad de equipos clasificados a llaves (Numérico, Obligatorio). <br> **3.** Método de emparejamiento inicial (Selección, Obligatorio).                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Datos de Salida**       | **1.** Bracket generado con partidos iniciales y fases posteriores (cuartos, semifinal, final) según aplique. <br> **2.** Partidos creados con equipos asignados y estado. <br> **3.** Actualización automática de cruces al avanzar ganadores de cada partido.                                                                                                                                                                                                                                                                                                                                             |
| **Flujo Básico**          | 1) El Organizador accede al torneo y entra al módulo “Llaves eliminatorias”. <br> 2) El sistema selecciona los equipos clasificados y confirma la generación. <br> 3) El Sistema valida que la cantidad de equipos sea compatible con eliminación directa. <br> 4) El Sistema genera **de forma aleatoria** los partidos iniciales y crea el cuadro (cuartos, semifinal y final según corresponda). <br> 5) El Sistema publica el bracket para consulta. <br> 6) Conforme se registren resultados de partidos, el Sistema asigna automáticamente los ganadores a la siguiente llave y actualiza el bracket. |
| **Flujo Alterno**         | 1) Si un partido termina en empate y no existe regla configurada para desempate, el sistema bloquea el avance de la llave y solicita al organizador definir el criterio de desempate o registrar el ganador. <br> 2) Si el organizador intenta regenerar llaves después de haber resultados registrados, el sistema debe impedirlo o requerir un reinicio explícito del bracket para evitar inconsistencias.                                                                                                                                                                                                |
| **Reglas de Negocio**     | 1) El sistema debe generar automáticamente los **partidos iniciales de manera aleatoria**. <br> 2) El sistema debe generar y mantener las fases de eliminación directa: **cuartos de final, semifinal y final**. <br> 3) El ganador de un partido avanza automáticamente a la siguiente ronda y actualiza el bracket. <br> 4) Una vez publicada la llave, los emparejamientos no deben cambiar, salvo acción administrativa controlada y con restricciones si ya existen resultados.                                                                                                                        |

| **Cómo se ejecutará**     | Mediante un módulo de “Estadísticas” accesible desde el torneo, con secciones para goleadores, historial de partidos y resultados por equipo.                                                                                                                                                                                                                                                                                             |
| **Actor principal**       | Usuario autenticado.                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Precondiciones**        | 1) Debe existir un torneo creado y visible para los usuarios. <br> 2) Para mostrar estadísticas con datos reales deben existir partidos con resultados registrados y, para goleadores, goles registrados por jugador.                                                                                                                                                                                                                     |
